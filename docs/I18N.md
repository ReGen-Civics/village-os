# Languages in Village OS

How a village reads in more than one language, what is translated where, and
how to add a language. Written 24 Nov 2026 for the site-wide Spanish pass.
`docs/I18N_STRATEGY.md` is the August spec that came before the build; read
this file for what is true now.

## Two kinds of words, two homes

| Words | Where they live | Who translates | Where it shows |
|---|---|---|---|
| The platform's own: buttons, headings, errors, every sentence in `client/src` | Lingui messages, `client/src/locales/<tag>.po` | a pull request; entries marked `# needs-native-review` until a native speaker has read them | every village on the image |
| The village's own: brochure and journey pages, role cards, the homepage words in Identity and the visit page (`village_doc`, `shared/villageDocTranslation.ts`) | the database, `content_translations` (migration 0387), one row per field per language | a person with the power that writes the English (`story.tell` for pages, `org.decide` for cards); anyone may suggest | that village only |

A platform string is wrapped with `<Trans>`, `t` or `msg` from
`@lingui/react/macro` and gets its translation in the PO file. A village's
words are translated in Admin, Translations, or proposed for a person to accept
at /admin/proposals (a `setting` proposal on `PUT /api/admin/content-translations`;
accepting runs that route as the person who accepts).

## The one registry

`shared/i18nLocales.ts`, `LOCALES`. Everything reads it:

- `lingui.config.ts` (which PO files extraction keeps);
- the default-language dial `village.default_locale` (its choices);
- one switch per language, `village.offer_locale.<tag>`, so each village chooses
  which languages it offers (Admin, Settings, Language; on by default);
- the server's catalog route and the shell's `lang` (`server/lib/i18nShell.ts`);
- the picker (`client/src/i18n/LanguagePicker.tsx`), through `LocaleProvider`,
  which narrows the platform's list to the village's `offeredLocales`.

Catalogs are compiled from every PO file at build time
(`scripts/build-i18n-catalogs.mjs`) and served from `/api/i18n/catalog/:locale`.

## The fallback chain

1. The reader's saved choice, then each browser language, then the village's
   default language, each matched to an offered tag (`es-CR` reads `es`), in
   `shared/i18nResolve.ts`.
2. A message the active catalog lacks renders its English source
   (`client/src/i18n/i18n.ts`, the moved English is merged under every catalog).
3. A village field with no translation in the reader's language renders its
   English, and the block carries `lang="en"` so a screen reader pronounces it
   as English (`fallbackLangOf` in `shared/contentTranslationOverlay.ts`,
   `usePageLang` in `client/src/hooks/usePageContent.ts`).

Number and date formats follow the browser's full tag (`es-CR`) even when the
catalog is the bare language.

## Adding a language

1. Add `{ tag: "<tag>", tier: "reviewed" }` to `LOCALES`.
2. Add `client/src/locales/<tag>.po` with translations of at least
   `OFFER_FLOOR` (30 percent) of the messages. `shared/i18nLocaleCoverage.test.ts`
   refuses the registry entry until the file reaches it, so the picker never
   offers a language that would show a visitor mostly English.

Nothing else changes. Optional, per language, where a village wants them:
applicant emails (`shared/applicantWords.ts`) and the companion lines
(`shared/companionLine.ts`) fall back to English for a language they do not
carry. A right-to-left script also needs the shell to mirror and a tested font
stack before it is offered (`docs/I18N_STRATEGY.md`, R15 and R34).

## Measuring

```
node scripts/i18n-coverage.mjs                  # every surface, grouped: shell, public, applicant, member, admin
node scripts/i18n-coverage.mjs --group public
node scripts/i18n-coverage.mjs --locale es --json
node scripts/i18n-coverage.mjs --files /resident
```

Per route in `client/src/App.tsx`: translated messages over all the copy its
files carry, wrapped or not. It does not count the village's own words in the
database; Admin, Translations shows those per page and card.

## Writing Spanish

- Costa Rican Spanish, `usted` for visitors, warm and plain.
- The glossary in `shared/applicantWords.ts`: aldea (village), la Carta de Amor,
  misión. Say aldea, tierra, hogar; never "desarrollo", "proyecto" or "unidades".
- House voice holds in Spanish too: no em or en dashes, no "no X sino Y" framing.
- Every new entry carries `# needs-native-review: <what>, <date>` above it until a
  native speaker has read it. `node scripts/i18n-coverage.mjs` counts them.
- A pull request adds its entries to `es.po` and never commits `en.po`; main
  regenerates `en.po` after the merge (`docs/GENERATED_DOCS.md`).
